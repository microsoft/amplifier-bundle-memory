The library now speaks store.v3. Four things changed, all in `src/amplifier_memory/` with tests and conformance probes behind each.

1. A store is an INSTANCE (§1). Which one a session uses is resolved in order: an explicit `home` from the caller (the modules' `config: home:`, or `--home`), else `$AMPLIFIER_MEMORY_HOME`, else the default `~/.amplifier-memory`. And your existing store is safe: while `~/.amplifier-memory` does not exist and `~/.amplifier/memory` does, the older path IS the default — so this device keeps reading and writing the store it already has, with nothing moved and nothing lost, until `init` offers to move it (that offer is cli.v3 §8, lane W; `legacy_store_present()` is the fact it asks about).

2. The instance carries its own `config.yaml` (§2, §11), written by `init` with the shipped defaults — `enabled: true`, and `llm: judge: {role: fast, provider: "", model: "", bundle: ""}`. The LLM knob moved out of `~/.amplifier/memory-config.toml` and into it, in YAML as you asked; configuration now travels with the instance it configures. A file that cannot be parsed still reports one honest reason and falls back to the defaults, and it leaves the instance ENABLED — a typo must never silently switch memory off.

3. `enabled: false` makes the instance inert (§11). `save`, `edit`, `forget`, `record_session` and the inbox's `append`/`accept`/`decline` all refuse with session.v4 §12's sentence, word for word: `memory is disabled for this instance (<path>: enabled: false).` Nothing is written, nothing is committed, and reading still works — §11 silences the session plane, it does not hide your memories.

4. A decline now keeps the quote (§7). `declined.md` lines read `- <date> <text>  quote: "<quote>"`, and a re-proposal is blocked on text OR quote. This closes a real leak: over 210 measured calls across 7 models, every re-proposal paraphrased the text while copying your sentence verbatim, so a suggestion you had already declined came back wearing new words and cost you a second decline. Lines written before v3 still parse and still block.

Also plumbing, not memory: `sessions.jsonl` records `{session_id, origin, first_seen}` once per session (idempotent — the first sighting wins) so the suggest job can tell a session with a human in it from a worker or recipe run. It is git-ignored, like `usage.jsonl`, so starting a session never leaves a commit behind; a store made before v3 starts ignoring it in one visible migration commit, once.

Seen working on this device: `uv run pytest -q` 316 passed (297 before this change), `ruff check` and `ruff format --check` clean, `conformance/store/run.py` exit 0 with all eleven clauses answered and §1/§2/§7/§11 Kept, `conformance/suggestions/run.py` and `conformance/cli/run.py` exit 0, and both module suites green (75 + 51).
