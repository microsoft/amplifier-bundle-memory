session.v4 §12 and §13 now hold in the two session-plane modules; §2's load line names a non-default instance. No library change — this consumes what lane U landed.

An app can now point a session at a memory instance from its mount plan: `config: home: <path>` on the inject hook and on the memory tool. With no `home:`, a session behaves exactly as it did before the key existed. Set the instance's `config.yaml` to `enabled: false` and the session plane goes quiet: nothing is injected, no line is rendered, nothing is written — and the tool refuses every operation, reads included, with one line naming the instance, the same sentence the library and the CLI use. The tool stays mounted while inert (a plan that names the module requires it to be there), but it advertises nothing: its description becomes that one line, so a switched-off instance costs a sentence per request instead of the full lesson on saving.

Any launcher — an app, a tmux wrapper, a recipe — can now declare what kind of session it is by exporting one variable, AMPLIFIER_SESSION_ORIGIN (human · worker · recipe · agent · eval). Unset means human, so nothing that exports nothing changes. At session start the hook writes one line per session to the instance's sessions.jsonl: {session_id, origin, first_seen}. A session that is not human still gets the memories — the work is still yours — but it cannot save, edit or forget, refused in the same shape a sub-agent is refused with the origin named instead, and it is shown no "suggestions waiting" line, because nobody is there to answer one. That closes the hole behind the measured case: 6 of the first timer night's 17 suggestions came from a tmux-launched worker.

When the plan names an instance that is not the default one, the line at the start of a session says which store answered: `3 memories loaded from ~/.amplifier-agent/memory. /memory to see them.` The default is never named and a session with no `home:` renders the old line byte for byte, so the common case reads exactly as it always has.
