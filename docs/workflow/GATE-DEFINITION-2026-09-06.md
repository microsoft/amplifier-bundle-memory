# The day-7 gate — pre-registered on day 0, before the number is known

Not a contract. A note written so the reading on 2026-09-13 is judged against a ruler cut
before anyone saw the number (product council D3; `outcome-cartographer`: "you may change a
metric's definition before you see the number, or you may see the number — never both").

- **Instrument:** `amplifier-memory status` on the steward's real store, run by the manager
  session, output pasted into CHECK-RECORD.
- **Day-0 reading (2026-09-06 17:20Z):** `memories 2 in MEMORY.md · written 5 (7d) ·
  forgotten 3 (7d) · kept 0` — two memories present (m-003, m-005), both written today.
- **kept** = a memory written ≥ 7 days before the reading and still present; an `edit` keeps
  the original write date (a refinement is continuity, not a new memory); a forget + re-save
  of the same intent counts once, from the first write. On 2026-09-13 the ceiling under the
  original rule is therefore **2**, not 5 — the gate as written cannot be met by a product that
  works perfectly all week unless the steward writes at least three more memories by 09-06/07.
- **What the reading decides:** it is a spike readout on a calibrated instrument, not a
  go/no-go on Phase 2 (bet-sizer). Phase 2 begins only on a reading the steward accepts as
  meaning what it says.
- **Also read on day 7:** citation rate (`cited`/`loaded`, once the instrument exists) and the
  steward's baseline — how often they repeated a standing preference per week before memory
  (asked 2026-09-06; the one number that cannot be taken later).
